# Project Audit — 2026-03-03

Full code audit across all files. Tier 1 fixes deployed same day.

## Tier 1 — FIXED (deployed 2026-03-03)

### #1. Early exit monitor throttled to 10s instead of 1s
**File:** `main.py:1429-1431`
**Status:** FIXED
**Impact:** The rate limiter gated the entire `_monitor_early_exit()` function, not just logging. Bid spikes last 5-8 seconds, so the 10-second effective poll interval missed most exit opportunities. Early exit is the primary profit engine (+$58/day).
**Fix:** Moved rate limiter to only gate `logger.info()`, exit trigger now runs every 1s as intended.

### #2. ML confidence dampening not applied
**File:** `main.py:1031-1036`
**Status:** FIXED
**Impact:** `CONFIDENCE_DAMPEN=0.6` was only wired to the legacy rule-based model. The active ML path received no dampening despite known ~10-20% overconfidence. Result: inflated bet sizing and fewer skipped low-signal windows.
**Fix:** Added `p_up = 0.5 + dampen * (p_up - 0.5)` after `predict_from_candles()`.

### #3. Streak guard checks wrong side (pre-flip)
**File:** `main.py:1143-1194`
**Status:** FIXED
**Impact:** `flip_signal` was always `None` when streak guard ran because regime flip executed 40 lines later. During trends, the guard paused the model's original side instead of the traded (flipped) side — protecting the wrong direction.
**Fix:** Moved regime flip before streak guard. Both streak guard and trend-conflict filter now use `effective_side` (post-flip).

### #5. Trend-conflict filter kills regime-flip opportunities
**File:** `main.py:1165-1179`
**Status:** FIXED (as part of #3)
**Impact:** Trend filter ran before regime flip and checked the model's original side. Model predicts DOWN in uptrend → filter rejects → flip never corrects to UP. The best flip opportunities were silently discarded.
**Fix:** Trend filter now checks `effective_side` (post-flip), so regime-flipped trades aligned with the trend pass through.

## Tier 2 — Fix this week

### #4. Double settlement race condition
**File:** `main.py:1504-1557` (early exit) and `main.py:1782-1830` (settlement)
**Status:** OPEN
**Impact:** Both `_monitor_early_exit` and `_settle_previous_window` can call `record_settlement()` for the same trade. No lock or coordination. If an early exit sell is in-flight (awaiting CLOB API) when the window ends, settlement queries DB before the early exit's DB update commits. Result: bankroll adjusted twice for the same trade.
**Fix:** Add `if live_pos.get("exited"): continue` in `_settle_live_trades_for_window()`, or use an asyncio Lock around both settlement paths.

### #7. `available_depth` double-counts best bid
**File:** `main.py:1499`
**Status:** OPEN
**Impact:** `best_bid_size` is added to `total_deep_size` which already includes it (since best_bid >= exit_threshold >= 0.45, it's always in the >= 0.85 filter). The 20-token minimum check passes at ~10 real tokens. Could trigger early exits into thin books → partial fills.
**Fix:** Remove `best_bid_size +` from the sum: `available_depth = total_deep_size`.

### #9. Maker fill settlements skip `record_settlement()`
**File:** `main.py:2147-2150`
**Status:** OPEN
**Impact:** `_settle_maker_fills_from_gamma` updates DB but never adjusts in-memory bankroll, loss counter, or recent outcomes list. Bankroll drifts from reality between 60-minute syncs.
**Fix:** Add `self.live_trader.record_settlement(won, pnl)` after the DB update.

### #12. `update_live_trade` silently swallows DB errors
**File:** `storage/db.py:524-554`
**Status:** OPEN
**Impact:** On DB failure, caller proceeds to update in-memory bankroll. On restart, DB doesn't reflect the settlement → catchup sweep settles it again → double P&L. Low probability but high impact.
**Fix:** Return a bool from `update_live_trade()`, check it in callers before adjusting bankroll.

## Tier 3 — Fix next week

### #6. Flipped signals use fabricated probability/edge values
**File:** `main.py:210-218`
**Status:** OPEN
**Impact:** `_build_flipped_signal()` hardcodes `our_prob = market_prob + 0.02` and uses regime strength as "confidence". Adaptive sizing uses this fake confidence for bet size. Flipped trades get arbitrary sizing unrelated to actual model output.
**Fix:** Design decision needed — what should confidence/edge represent for regime-flip trades? Options: (a) pass through regime strength transparently and document it drives sizing, (b) use a fixed moderate confidence for all flip trades.

### #8. `sell_winning_tokens` passes wrong amount type
**File:** `strategy/live_trader.py:681-695`
**Status:** OPEN
**Impact:** Computes `est_tokens * 0.99` (mixing token count with price) but SELL expects token count. Works accidentally at mid prices but fails at extremes. Compare to `sell_early_exit()` which correctly queries actual token balance.
**Fix:** Query actual token balance via `get_token_balance()` before selling, like `sell_early_exit` does.

### #10. `btc_end` undefined in stale settlement (landmine)
**File:** `main.py:1941-1942`
**Status:** OPEN
**Impact:** If all iterations of the stale settlement loop resolve via Gamma API, `btc_end` is never assigned. Python short-circuits `btc_end if not gamma_res else None` today (because `gamma_res` is truthy), but any refactor will crash with `UnboundLocalError`.
**Fix:** Add `btc_end = None` at the top of each loop iteration.

### #11. No Binance data staleness detection
**File:** `data/binance_ws.py`
**Status:** OPEN
**Impact:** `get_latest_price()` returns the last-known price with no age check. After a WebSocket disconnect, the price could be minutes old. Downstream uses: trend-conflict filter, window start price. Chainlink has staleness detection; Binance has none.
**Fix:** Add `_last_data_ts` field, update on each message. Add age check in `get_latest_price()` that returns None if data is stale (e.g., > 30s).

## Medium priority (robustness hardening)

### M1. `_market_cache` + `_fee_rate_cache` grow unbounded
**File:** `data/polymarket.py:100-102`
**Impact:** ~860 entries/day, no eviction. After months of uptime, thousands of stale entries.
**Fix:** Use LRU cache or prune entries older than 1 hour.

### M2. Binance backoff cap too low (8s)
**File:** `data/binance_ws.py:35`
**Impact:** During sustained outage, hammers endpoint every 8s → risk of IP ban.
**Fix:** Increase `_BACKOFF_MAX` to 60s.

### M3. Chainlink RTDS fixed 5s reconnect, no backoff
**File:** `data/polymarket.py:648`
**Impact:** Worsens 429 rate limit storms (already happening).
**Fix:** Exponential backoff with cap (e.g., 5s → 10s → 20s → 60s max).

### M4. `/analyze` blocks event loop with sync sqlite3
**File:** `main.py:713-723`
**Impact:** Blocks all coroutines (early exit, WebSocket, Telegram) during query.
**Fix:** Use `asyncio.to_thread()` wrapper or the existing aiosqlite connection.

### M5. Schema migration catches all exceptions
**File:** `storage/db.py:202-208`
**Impact:** Disk full, permission errors silently swallowed during migration.
**Fix:** Catch only `OperationalError` or check for "duplicate column" in error message.

### M6. `save_market_snapshot` commits every 3s
**File:** `storage/db.py:681-726`
**Impact:** ~28K fsync/day. Unnecessary disk I/O.
**Fix:** Batch commits (every 10 snapshots or on a timer).

### M7. Regime detector has no hysteresis
**File:** `signals/regime.py:66-71`
**Impact:** Can flip-flop between "trending" and "ranging" when strength oscillates around threshold.
**Fix:** Add hysteresis band (e.g., enter trending at 0.30, exit at 0.25).

### M8. Fire-and-forget `save_candle` task has no error handler
**File:** `main.py:374`
**Impact:** If `save_candle` raises, candle data silently lost. Missing candles degrade ML features.
**Fix:** Add exception handler to the task or await it.

### M9. No table retention/pruning
**File:** `storage/db.py`
**Impact:** `market_snapshots` grows 10.5M rows/year. Query performance degrades over months.
**Fix:** Add periodic cleanup (e.g., keep 7 days of snapshots, archive rest).

### M10. No WAL mode on SQLite
**File:** `storage/db.py`
**Impact:** Default journal mode means writers block readers.
**Fix:** Add `PRAGMA journal_mode=WAL` after connection open.

### M11. Shutdown calls `stop()` twice
**File:** `main.py:2427, 2440`
**Impact:** Signal handler and finally block both call `stop()`. Could double-close aiosqlite.
**Fix:** Add a `_stopped` flag, check it at start of `stop()`.

### M12. `_live_trade_tokens` not restored on restart
**File:** `main.py`
**Impact:** Positions from prior sessions never get early exit monitoring after restart.
**Fix:** On startup, query DB for unsettled live trades and populate `_live_trade_tokens`.
